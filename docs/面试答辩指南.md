# 低照度 RAW ISP 面试答辩指南

**Project:** Low-light RAW ISP  
**Author:** Guozh  
**Version:** Interview-v0.1.0  
**Date:** 2026-09-28

## 一分钟项目介绍

我基于 SID Sony 官方 RAW 配对数据，完成了一个部署感知型低照度 RAW-to-sRGB ISP 原型。输入是极暗的短曝光 Bayer RAW，参考是真实长曝光 RAW。项目先实现黑电平校正、曝光补偿、白平衡、去马赛克和 tone mapping，再标定 Poisson-Gaussian 噪声模型，并以 Gaussian 和噪声感知 Wiener 作为传统基线。学习部分采用 4 通道 packed RAW 残差 U-Net，在严格按场景划分的测试集上明显优于传统方法。工程侧实现了 CUDA AMP、带 halo 的分块推理和 tile batching；在 RTX 3060 Ti 上，最终 6 张跨 ISO Release Smoke Test 全部成功，模型推理均值约 0.541 秒，峰值显存约 4.27 GiB。项目还通过 PSNR、SSIM、DeltaE、LPIPS、暗部彩噪和参数扰动评估失败模式，并明确没有把工作站原型包装成量产 ISP。

## 五分钟讲解结构

### 1. 问题定义

低照度短曝光能减少运动模糊，但光子数量少，会产生明显的信号相关噪声、读出噪声和颜色失真。本项目的任务不是对普通 JPEG 做滤波，而是在去马赛克之前直接处理线性 RAW，使算法能利用真实传感器数据。

### 2. 数据与防止泄漏

- 数据：SID Sony 官方短曝光/长曝光 RAW 配对数据。
- 划分：train/val/test 为 161/20/50 个独立场景。
- 输入：R/G1/G2/B 四通道 packed Bayer RAW。
- 参考：长曝光 RAW，不是人工合成的干净图。
- 场景之间无交集，避免同一场景不同曝光文件跨集合造成数据泄漏。

### 3. 传统基线

使用异方差噪声模型：

```text
variance = a * signal + b
```

其中 `a` 表示随信号增强的散粒噪声，`b` 表示近似与信号无关的读出噪声底。基于该模型实现噪声感知 Wiener，并与固定 Gaussian 比较。ISO 200 和 ISO 8000 的独立场景上，Wiener 在 PSNR、SSIM、DeltaE 和梯度相似度四项指标均 3/3 胜过 Gaussian。

### 4. 学习型方法

- 模型：约 227 万参数的残差 U-Net，输入输出均为四通道 packed RAW。
- 损失：正式模型使用 Charbonnier；另训练 Edge + Chroma 的 Detail 消融模型。
- 训练：256×256 patch、batch 12、AMP、20 epochs。
- 最佳验证 Charbonnier loss：0.0130951。
- Detail 模型只在部分高 ISO 指标上略有改善，综合 LPIPS 和低 ISO 表现后没有替换正式模型。

### 5. 评价方法

不能只看一个 PSNR：

| 指标 | 主要回答的问题 |
|---|---|
| RAW PSNR/MAE | 线性 RAW 数值是否接近参考 |
| 显示 PSNR | 最终显示图整体误差多大 |
| SSIM | 结构和局部对比度是否相似 |
| DeltaE2000 | 人眼感知的颜色误差多大 |
| LPIPS | 深层特征上的感知差异多大 |
| 梯度相似度 | 边缘和纹理是否被过度抹平 |
| 暗部高频 STD | 阴影区域残留亮度噪声多少 |
| R-G/B-G STD | 暗部彩噪多少 |

指标必须结合局部裁剪图判断。高 PSNR 可能来自过度平滑，梯度值高也可能来自残留噪声，因此没有单个指标可以完全替代人工观察。

### 6. 部署结果

正式配置：PyTorch CUDA + AMP，tile=512，halo=32，tile batch=6。

| Release Smoke Test | 结果 |
|---|---:|
| 成功/失败 | 6/0 |
| 模型推理 mean/p50/p95 | 0.541/0.543/0.552 s |
| 总延迟 mean/p50/p95 | 2.622/2.466/3.189 s |
| 吞吐率 | 0.3814 images/s |
| 峰值显存 | 4.273 GiB |

模型推理只占端到端耗时的一部分。当前主要瓶颈是 CPU 去马赛克、tone mapping 和 PNG 编码，因此仅优化神经网络不能成比例降低总延迟。

## 关键技术决策

### 为什么在 RAW 域降噪

RAW 保留近似线性的传感器响应和 Bayer 结构；去马赛克会把单像素噪声传播到多个颜色通道，tone mapping 又会放大暗部噪声。先在 RAW 域处理更容易建立物理噪声模型，也能减少彩色伪影。

### 为什么使用 packed RAW

将 2×2 Bayer 单元打包成 R/G1/G2/B 四通道，可将空间尺寸各缩小一半，同时保持每个 CFA 通道独立，适合普通卷积网络处理。G1 和 G2 不应在输入阶段强行合并，因为它们位于不同空间位置。

### 为什么使用残差学习

输入已经包含场景主体，网络主要估计噪声和局部校正量。残差结构比直接从零生成干净 RAW 更容易优化，也能降低无必要的内容重建风险。

### 为什么需要 halo

大图分块推理时，tile 边缘缺少卷积上下文，直接拼接会产生接缝。推理时为每个 tile 增加重叠 halo，只保留中心有效区域，从而降低边界伪影。

### 为什么 ONNX 没有加速

ONNX 是模型交换格式，不是加速器。当前 ONNX Runtime 只有 CPU provider；实际基准中 ONNX CPU 均值 1.073 秒，PyTorch CPU 为 0.857 秒，因此正式后端仍使用 PyTorch CUDA。要评估 GPU 部署，需要匹配 CUDA 的 ONNX Runtime GPU 或 TensorRT，并在目标硬件上重新测量。

## 失败实验与工程判断

### CCM 为什么关闭

启用当前 RAW 元数据推导的 CCM 后，ISO 200 三场景 U-Net 的 PSNR 从 32.306 降到 28.455，DeltaE 从 3.927 上升到 7.200，LPIPS 从 0.144 上升到 0.206。说明该矩阵与当前参考渲染链路不匹配，因此保留实验分支但不默认启用。

### Detail 模型为什么没有部署

增加 Edge 和 Chroma loss 后，高 ISO 的部分 SSIM/DeltaE 略有改善，但 ISO 200 综合指标下降，LPIPS 也没有稳定获益。项目选择整体更稳定的原最佳 U-Net，而不是只挑有利指标替换模型。

### 鲁棒性暴露了什么

- 曝光和白平衡 ±5%：总体可容忍。
- ISO 200 黑电平偏低 1%：PSNR 从 32.306 降到 22.736，属于明显风险。
- 额外噪声 1.5 倍：ISO 200 PSNR 降到 22.469，说明噪声分布漂移是核心泛化问题。
- ISO 8000 本身噪声更强，模型基线与长曝光参考的差距更大。

## 高频追问

### 这是完整 ISP 吗

不是量产完整 ISP。它覆盖了低照度 RAW 处理的关键链路和部署原型，但没有实现镜头阴影校正、坏点校正、自动曝光、自动白平衡、HDR、多帧对齐、锐化和目标硬件上的实时流水线。

### 为什么长曝光参考也可能不够清晰

长曝光能提高信噪比，但运动物体可能产生模糊，固定场景也可能存在轻微相机抖动或配准误差。因此长曝光是高质量监督参考，不代表每个局部都是绝对锐利的真实值。

### 为什么不能只按肉眼评价

肉眼评价受显示器、缩放比例、观察区域和个人偏好影响；客观指标能提供可重复比较。但指标也可能奖励过度平滑，所以需要“全参考指标 + 暗部失败指标 + 局部裁剪 + 人工观察”共同判断。

### 项目最大的不足是什么

尚未完成真实跨相机 RAW 数据验证。当前已完成 Sony 同相机测试集和参数扰动测试，只能证明同传感器分布下的泛化及部分参数鲁棒性，不能宣称对不同 CFA、黑电平、颜色响应和噪声特性的相机均有效。

### 下一步如何提高工业价值

优先级依次是：接入另一款真实相机 RAW 并建立适配层；加入 ISO/噪声参数条件输入；优化 CPU 显示链路或迁移到 GPU；在目标硬件上测试 TensorRT FP16；最后再考虑多帧降噪和运动场景。
