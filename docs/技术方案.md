# 真实低照度 RAW ISP 项目技术方案

> 本文记录项目初始设计。项目当前状态和后续模块顺序以
> `docs/工程主线与补全计划.md` 为准；后续不再横向新增孤立 Phase，而是补全
> Phase 1 RAW 前端、Phase 2 颜色重建和 Phase 7 输出后端。

## 1. 项目定位

本项目实现一个面向真实低照度场景的 RAW-to-sRGB ISP 原型。输入相机传感器产生的 Bayer RAW 数据，经过黑电平校正、噪声处理、白平衡、去马赛克、颜色校正和 tone mapping，输出可观看、可测量、可部署的 sRGB 图像。

第一版不追求覆盖所有 ISP，也不直接宣称量产级效果。项目重点是掌握一条完整、可解释的工程链路：

```text
真实数据 -> RAW 解码 -> 传统 ISP 基线 -> 学习型模块 -> 画质评估 -> ONNX/TensorRT 部署
```

第一版的核心问题是：在夜间或极低照度下，提亮图像的同时控制噪声、颜色偏差和高光溢出。

## 3. 目标数据集与数据规范

### 3.1 SID：主训练数据

SID（See-in-the-Dark）包含真实极低照度 RAW 和较长曝光参考图，适合学习短曝光 RAW 到高质量图像的映射。主任务可以定义为：

```text
短曝光 RAW -> 参考 RGB/RAW
```

需要记录每个样本的相机型号、曝光时间、ISO、黑电平、白电平和 Bayer pattern。不能随机把同一场景的相邻帧拆到训练集和测试集，否则会造成数据泄漏。

### 3.2 SIDD：真实噪声泛化验证

SIDD（Smartphone Image Denoising Dataset）提供真实手机噪声及参考图像，用来验证模型是否只记住 SID 的相机和场景。第一版可以只使用它的验证子集或少量训练数据，重点是跨数据集测试。

### 3.3 数据处理原则

1. 原始 RAW 保持只读，不覆盖原文件。
2. 训练输入使用线性、归一化后的浮点数据，不在训练前做 JPEG 压缩。
3. 采用按场景/相机划分的 train/val/test，而不是简单随机按 patch 划分。
4. 每次预处理保存一个 manifest，记录文件、尺寸、相机、ISO、曝光和划分。
5. 先用 100～500 个样本跑通全流程，再扩充数据规模。

## 4. 专业概念说明

### 4.1 RAW、Bayer 和 sRGB

相机传感器通常每个像素只测量一种颜色，按照 RGGB 等 Bayer pattern 排列。RAW 是传感器的线性测量值，还没有完成颜色插值、白平衡和显示变换。

sRGB 是面向显示和存储的标准 RGB 图像。它已经完成了颜色变换和非线性 gamma，不能把 sRGB 像素值直接当作物理亮度。

### 4.2 黑电平和白电平

黑电平是传感器在没有光照时的基线偏置；白电平近似表示可用的饱和上限。常见归一化公式为：

```text
raw_linear = (raw - black_level) / (white_level - black_level)
```

如果黑电平处理错误，暗部会出现灰雾或颜色偏差；如果白电平处理错误，曝光和高光判断会失真。

### 4.3 白平衡

不同颜色通道对同一光源的响应不同。白平衡通过对 R/G/B 乘以不同增益，使中性物体尽量呈中性。AWB（自动白平衡）是根据图像或元数据估计这些增益。

### 4.4 去马赛克（Demosaicing）

去马赛克把单通道 Bayer 采样恢复为三通道 RGB。简单双线性方法速度快但容易丢细节；更复杂的方法可能产生伪色、拉链纹和边缘伪影。第一版先实现双线性作为基线，再尝试 Malvar 或轻量学习型去马赛克。

### 4.5 降噪

低照度噪声通常同时包含光子噪声和读出噪声，不能只用固定强度的高斯滤波。RAW 域降噪的优势是数据仍然是线性的，噪声模型更清晰；RGB 域降噪实现简单，但容易把颜色和细节一起抹掉。

### 4.6 Tone mapping

Tone mapping 将线性 HDR/RAW 动态范围压缩到显示器可显示的范围。它决定暗部提亮、高光压制和局部对比度。全局曲线稳定易解释；局部 tone mapping 更能提升暗部，但容易产生光晕和局部不一致。

### 4.7 3A

3A 指 AE（自动曝光）、AWB（自动白平衡）和 AF（自动对焦）。本项目第一版聚焦 AE/AWB 相关的曝光与颜色，不实现 AF。3A 的共同特点是它们是“估计参数并反馈到图像管线”，不是单一神经网络输出一张图。

## 5. 项目阶段（Phase）

### Phase 0：环境恢复与可复现实验框架

目标：确保 GPU 和 Python 环境可用。

任务：

1. 重启系统，确认 `nvidia-smi` 能显示 RTX 3060 Ti 和 8 GiB 显存。
2. 使用独立虚拟环境，建议 Python 3.11 或 3.12，不直接依赖系统 Python 3.14。
3. 安装 PyTorch CUDA、NumPy、OpenCV、rawpy、scikit-image、PyYAML、TensorBoard、ONNX。
4. 编写 `scripts/env_check.py`，检查 CUDA、随机种子、读写权限和磁盘空间。
5. 建立 Git 忽略规则，排除 `data/raw`、`checkpoints` 和大体积输出。

验收标准：

- `nvidia-smi` 正常；
- `torch.cuda.is_available()` 为 True；
- 能在 GPU 上完成一个随机张量计算；
- 一条命令能记录 git commit、配置文件和运行环境。

### Phase 1：RAW 读取与传统 ISP 基线

目标：不用深度学习，得到稳定、可解释的基线图像。

任务：

1. 读取 SID RAW 和元数据。
2. 实现黑电平/白电平归一化。
3. 实现 Bayer packed 4 通道表示。
4. 实现固定白平衡和简单自动白平衡。
5. 实现双线性去马赛克。
6. 实现颜色矩阵、gamma 和基础 tone mapping。
7. 保存每个中间结果，便于定位问题。

验收标准：

- 输入不同尺寸 RAW 不崩溃；
- 中间结果没有 NaN/Inf；
- 输出颜色和曝光基本合理；
- 能解释每个模块改变了什么。

### Phase 2：曝光、颜色与 tone mapping

目标：建立可复用的场景线性 ISP 后处理链路，并与 SID 长曝光参考进行定量比较。

任务：

1. 从 SID manifest 自动解析短长曝光配对和物理曝光比。
2. 在 tone mapping 前保留超过显示白点的场景线性高光。
3. 实现 Reinhard tone mapping、亮度统计和曝光校准。
4. 实现相机颜色矩阵（CCM）并评估其对色差和彩噪的影响。
5. 建立 PSNR、SSIM、DeltaE2000、近黑和近白比例等指标。

验收标准：

- 短曝光与长曝光经过相同 ISP 后可以对齐评估；
- 曝光、tone mapping 和 CCM 的作用能够分别解释；
- 不以牺牲噪声和结构为代价盲目匹配中位亮度；
- CCM 在 RAW 降噪完成前可以安全关闭。

### Phase 3：真实低照度噪声建模与传统降噪

目标：理解并测量真实噪声，而不是只调用滤波器。

任务：

1. 比较不同 ISO 和曝光条件下的噪声。
2. 统计暗部区域均值与方差。
3. 拟合简化的异方差噪声模型：

```text
variance(signal) = a * signal + b
```

其中 `a` 可近似表示光子噪声项，`b` 表示读出噪声项。

4. 比较 RAW 域和 RGB 域降噪。
5. 实现一个传统基线，如高斯/双边滤波或 Non-Local Means。

验收标准：

- 能画出信号均值-噪声方差曲线；
- 能根据 ISO 或亮度改变降噪强度；
- 不把噪声误认为细节；
- 有噪声前后局部裁剪对比图。

### Phase 4：学习型 RAW 降噪

目标：只让神经网络解决传统规则最困难的 RAW 降噪问题。

任务：

1. 输入 4 通道 Bayer packed patch，尺寸从 256×256 开始。
2. 使用轻量 U-Net 或残差网络。
3. 使用 L1/Charbonnier 损失作为主损失，辅以 SSIM 或边缘损失。
4. 开启 AMP 混合精度，监控显存和训练速度。
5. 保存最佳验证集模型，不只保存最后一个 epoch。
6. 与 Phase 1 的传统 ISP 结果比较。

推荐损失：

```text
L = L_charbonnier + 0.2 * L_ssim + 0.05 * L_edge
```

第一版不要堆太多损失。先确认主损失能够下降、结果没有颜色漂移，再逐步加入辅助项。

### 可选研究扩展：自适应 tone mapping

目标：让系统针对不同亮度和噪声水平自动选择合理的提亮曲线。

任务：

1. 设计固定曲线基线，如 gamma、Reinhard 和简单分段曲线。
2. 用一个小网络预测曲线参数，而不是直接生成整张图。
3. 对参数范围做约束，避免出现负增益或过度提亮。
4. 比较固定曲线和自适应曲线在暗部细节、高光饱和和色差上的差异。

验收标准：

- 不同 ISO/曝光的图像不需要人工逐张调参；
- 暗部明显可见但噪声不过度放大；
- 高光区域不大量溢出；
- 曲线参数有记录、可解释、可复现。

### Phase 5：综合画质评估

目标：建立图像处理领域的评价习惯，而不是只看截图。

指标解释：

- **PSNR**：均方误差的对数表达，越高通常越接近参考图，但不完全符合人眼感受。
- **SSIM**：比较亮度、对比度和局部结构，范围通常为 0～1，越高越好。
- **LPIPS**：使用深度特征衡量感知差异，通常越低越好，更接近“看起来像不像”。
- **ΔE**：颜色空间中的色差，越低表示颜色偏差越小；应说明使用的色彩空间和版本。
- **饱和像素比例**：超过白电平或显示上限的像素比例，用于衡量高光溢出。
- **暗部噪声标准差**：在均匀暗部区域统计噪声，越低通常越干净，但必须结合细节保持判断。
- **边缘保持**：比较边缘梯度或高频结构，防止降噪把细节抹掉。

测试方式：

1. SID 内部测试：检验同分布效果。
2. 按 ISO、曝光、场景分别统计，不只给一个总平均数。
3. 同时保存数值指标、全图和局部 crop。
4. 记录失败案例：色偏、伪色、光晕、过度平滑、过曝。

### Phase 6：跨数据集泛化

目标：验证模型是否只记住 SID Sony 相机与训练场景。

任务：

1. 使用 SIDD 验证子集测试真实手机噪声。
2. 明确处理不同 Bayer pattern、黑白电平、ISO 定义和颜色空间。
3. 分开报告同分布与跨相机结果，不通过混合平均数掩盖退化。
4. 记录失败案例并分析域差异来自噪声、颜色还是 tone mapping。

### Phase 7：部署与工程化

目标：把研究代码变成可运行的图像处理工具。

任务：

1. 导出 ONNX。
2. 使用 TensorRT FP16 构建 engine。
3. 测试 PyTorch、ONNX Runtime 和 TensorRT 的耗时。
4. 统计峰值显存、参数量和输入分辨率。
5. 提供批量目录推理命令。
6. 固定配置、模型版本和数据版本，生成可复现实验报告。

验收标准：

- 同一输入在 PyTorch 和 TensorRT 结果误差可解释；
- 失败输入有明确报错；
- 1080p 图像可以稳定处理；
- README 能让别人从环境检查运行到结果生成。

## 6. 评价结果应该如何解读

不要单独追求 PSNR 最高。低光 ISP 的实际取舍通常是：

```text
更亮 <-> 更大噪声
更锐 <-> 更多伪影
更强降噪 <-> 更少细节
更高动态范围 <-> 更复杂的融合和鬼影问题
```

一份可信报告至少要同时回答：

1. 图像是否比传统基线更干净？
2. 暗部细节是否保留？
3. 颜色是否稳定？
4. 高光是否溢出？
5. 换相机或换数据集后是否仍然有效？
6. 推理速度和显存是否可以接受？

## 7. 推荐的最小可行版本（MVP）

不要一次启动全部 Phase。建议 MVP 只包含：

1. SID 少量数据读取。
2. 黑电平、白电平、白平衡、双线性去马赛克。
3. 固定 gamma/tone mapping。
4. 传统 RAW 降噪基线。
5. 轻量 U-Net RAW 降噪。
6. PSNR、SSIM、LPIPS 和暗部 crop 对比。
7. GPU 推理脚本和实验日志。

MVP 跑通之后再扩充 SID 全量、SIDD 泛化和 TensorRT 部署。这样即使后续某个数据集下载或驱动配置出现问题，也不会让整个项目停滞。

## 8. 暂不做的内容

第一版明确不做：

- 自动对焦；
- 多摄像头环视；
- 复杂多帧 HDR；
- 大型 Transformer；
- 目标检测联合训练；
- 4K/8K 实时视频；
- 声称达到 DJI、影石、海康的量产 ISP 水平。

这些内容可以在第一版稳定后作为扩展，而不是一开始分散主线。
