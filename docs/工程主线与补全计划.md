## 1. 文档定位

本文档是项目后续开发的唯一主路线图。原 Phase 编号保留，用于追溯实验和输出目录；新增工作优先补回原有 Phase，不再为每个算法单独建立互不相连的新 Phase。

项目最终要形成两条共享输入、共享指标、共享部署框架的路径：

1. **传统 ISP reference path**：用于学习基本功、逐级调试和建立可解释基线；
2. **Learned low-light path**：只在 RAW denoise 这一困难模块替换传统算法，其余模块尽量复用传统 ISP 后端。

## 2. 关于“标准 ISP 顺序”

ISP 没有全球唯一、所有芯片完全相同的固定顺序。HDR merge、LSC、AWB gain、LDC、tone mapping 和 sharpen 的位置会随传感器、硬件数据流和产品目标变化。但以下数据依赖是稳定的：

- BLC 必须在线性 RAW 中尽早完成，否则后续增益会放大黑电平误差；
- DPC 应在强增益、LSC 和插值前处理，避免坏点被放大或扩散；
- RAW denoise 通常位于 demosaic 之前，避免噪声传播到三个颜色通道；
- demosaic 是 Bayer RAW 到 RGB 的域边界；
- CCM 在线性 RGB 中工作，gamma 编码不能提前；
- YCbCr/YUV 输出位于 RGB 颜色处理之后；
- AWB 是“统计估计 + 参数反馈”的控制环，不能只画成一个串行滤波块。

公开实现也体现了“代表性主干而非唯一顺序”。AMD/Xilinx Vitis Vision 的 `isppipeline` 示例实际串接了 BLC、gain control、demosaic、AWB、CCM、tone/quantization 和 gamma；其 AWB 在 RGB 域执行。另一些产品将 AWB 估计得到的 R/B gain 反馈到 Bayer RAW gain block。因此本文同时区分 **AWB estimation** 和 **WB gain application**。

参考：

- AMD/Xilinx Vitis Vision ISP pipeline：<https://github.com/Xilinx/Vitis_Libraries/blob/main/vision/L1/examples/isppipeline/xf_isp_accel.cpp>
- IMX708 工程型参考实现：<https://github.com/serious-engineer/imx708-rpi-isp-pipeline>

## 3. 本项目采用的主数据流

```text
Sony ARW + metadata
        |
        v
[RAW ingest]
bit depth / Bayer pattern / black-white metadata validation
        |
        v
[BLC] 每 CFA 通道黑电平校正 + 白电平归一化
        |
        v
[DPC] hot/dead pixel 检测与修复
        |
        v
[LSC] lens shading gain map（无标定时 identity bypass）
        |
        v
[Digital gain] SID 短/长曝光比补偿，记录 requested/applied gain
        |
        +---------------------- RAW statistics ----------------------+
        |                                                            |
        v                                                            v
[RAW denoise selector]                                       [3A/AWB estimation]
none / Gaussian / Wiener / learned U-Net                    metadata / Gray World /
        |                                                   Shades-of-Gray / Gray Edge
        |                                                            |
        +---------------------- WB gains <----------------------------+
        |
        v
[WB gain application] R/G1/G2/B gain
        |
        v
[Demosaic] Bilinear / MHC / Edge-aware
        |
        v
===================== Bayer RAW -> linear Camera RGB =====================
        |
        v
[RGB cleanup] false-color suppression / optional mild chroma denoise
        |
        v
[CCM] Camera RGB -> linear target RGB（必须经过标定/验收）
        |
        v
[Tone mapping] scene range -> display range
        |
        v
[OETF/Gamma] linear RGB -> nonlinear sRGB
        |
        v
[Optional geometry] LDC / crop / resize
        |
        v
========================== RGB -> YCbCr ================================
        |
        v
[Y/C processing] optional YNR / CNR / luma sharpen with overshoot control
        |
        v
[Format] full/limited range + 4:4:4 / 4:2:2 / 4:2:0 + NV12/I420
        |
        v
[Output] PNG or H.264/H.265 media pipeline
```

### 3.1 为什么这样安排

- **DPC 在 LSC 和 digital gain 前**：避免一个坏点经增益变成强亮点，再被后续插值扩散。
- **LSC 接口位于 RAW denoise 前**：这是代表性的硬件 ISP 顺序；但 LSC 会同时放大信号和噪声，因此噪声模型必须感知 gain map。当前没有真实 LSC 标定时默认 identity，不改变已训练 U-Net 的输入分布。
- **曝光补偿在 U-Net 前**：这是 SID 低照度任务已经验证的训练定义，不应为了形式上的标准顺序随意移动。
- **WB gain 在 demosaic 前**：复用当前 packed RAW 路线；AWB 的估计过程独立，不再把 metadata WB 称为“自动白平衡算法”。
- **CCM 在 tone/gamma 前**：CCM 假设输入是线性 RGB；对已经 gamma 编码的 sRGB 直接乘矩阵不符合当前颜色模型。
- **LDC 单列为 geometry**：几何畸变校正不是 CCM 的下一个颜色模块，实际可位于 RGB/YUV 或独立 warp 单元。
- **YNR/CNR 默认可 bypass**：已有 RAW denoise 较强，后端再次降噪可能抹除纹理，必须用消融实验决定是否启用。

## 5. 不新增孤立 Phase 的补全方式

### 5.1 重新打开 Phase 1：RAW 前端基本功

按以下顺序完成，每一步都输出 stage dump 和 JSON 参数：

1. **BLC 工程化**：保留当前每 CFA 通道 metadata BLC，增加输入 bit depth、范围、NaN/Inf、近黑和饱和统计。
2. **DPC**：支持 hot/dead pixel；用人工注入的已知坏点计算 precision、recall、修复 MAE，并检查正常纹理误杀。
3. **LSC interface**：支持四通道二维 gain map、identity bypass 和径向模拟测试；等待真实平场 RAW 后才做真实标定。
4. **统一中间结果**：`raw_ingest -> blc -> dpc -> lsc` 使用相同 dtype、范围和 CFA contract。

Phase 1 完成标准不是“能出图”，而是每一级都能单独开关、记录参数、保存中间结果并通过合成缺陷回归测试。

### 5.2 重新打开 Phase 2：颜色重建基本功

1. **区分 AWB estimate 与 WB apply**：camera metadata 作为基线；实现 Gray World、Shades-of-Gray、Gray Edge。
2. **AWB 评价**：排除饱和/近黑像素，报告 R/G、B/G gain、灰点角误差、DeltaE 和失败场景。
3. **Demosaic 对比**：保留 Bilinear，增加 MHC 和一种 edge-aware 方法；评价 PSNR/SSIM、斜边 zipper、false color、运行时间。
4. **CCM 重做**：没有 ColorChecker/可靠标定数据前保持关闭；先把矩阵方向、白点、线性域和裁剪顺序测试清楚。
5. **LDC 独立接口**：只有获得相机内参和畸变系数后再验收，不与 CCM 混在一个颜色阶段。

### 5.3 Phase 3 和 Phase 4：不推倒重训，接回主线

- Phase 3 Wiener 与 Phase 4 U-Net 共享同一个 `RAW denoise selector`；
- DPC/LSC 新模块首先以 bypass/identity 接入，确保旧 checkpoint 逐像素回归一致；
- 真实 LSC 启用后，重新标定噪声传播并检查 U-Net 分布偏移，再决定是否微调；
- 不为了补传统 ISP 重训已经验收通过的 U-Net。

### 5.4 Phase 5 和 Phase 6：作为所有模块的统一验收层

- Phase 5 增加 DPC、AWB、demosaic、LSC 专项指标，但保留现有 PSNR/SSIM/DeltaE/LPIPS 主框架；
- Phase 6 增加坏点密度、LSC gain、色温和 Bayer pattern 扰动；
- 外部 RAW 数据未取得前，不写“真实跨相机完成”。

### 5.5 扩展 Phase 7：YCbCr 与媒体输出后端

顺序为：

```text
sRGB/RGB
-> BT.709 YCbCr（同时测试 full/limited range）
-> optional YNR/CNR
-> luma sharpen + overshoot/ringing guard
-> 4:2:0
-> NV12/I420
-> FFmpeg H.264/H.265 smoke test
```

编码属于 media pipeline，不属于 RAW 降噪算法。验收同时报告颜色 round-trip 误差、stride/plane 大小、文件可解码性和端到端耗时。

### 9.3 不能用公共数据替代的标定

- **真实LSC**：需要目标相机、镜头、焦距、光圈和色温条件下的均匀平场RAW；
- **量产CCM**：需要目标相机拍摄ColorChecker并明确参考光源、白点和目标色彩空间；
- **LDC**：需要目标相机/镜头的棋盘格或标定板数据；
- **跨相机泛化**：需要第二款真实RAW相机数据，而不是把sRGB/JPEG假装成RAW。

这些数据未取得时，实现接口、合成测试和bypass，但结论必须标为“未完成真实标定”。

## 10. 训练策略最终决定

### 10.1 当前正式模型冻结

继续使用：

```text
checkpoints/phase4_learning/b48_bs12_fair/raw_denoiser_best.pt
```

当前不重新训练，原因是：

1. 模型已经通过train/val/test场景隔离和多指标验收；
2. DPC、AWB、Demosaic、CCM和YCbCr都是传统pipeline补全，不需要训练；
3. LSC初版为identity，理论上不改变模型输入；
4. 保持checkpoint不变才能明确判断新增传统模块是否造成回归。

### 10.2 只有以下情况触发微调

- 启用真实非identity LSC后，输入噪声和空间亮度分布改变；
- 接入第二款相机RAW，需要camera/noise conditioning；
- 新DPC策略改变了大量训练输入像素；
- 在固定测试集上确认输入域偏移，而不是仅凭主观感觉。

若触发训练，必须从当前正式checkpoint开始微调，保留旧模型作为对照，不覆盖原权重。

### 12.4 最终可对外表述

> 基于SID Sony官方RAW数据，构建了一套模块化低照度RAW ISP工作站原型：既包含可解释的传统传感器前端、颜色重建和YCbCr输出链路，也包含真实噪声标定、Wiener与学习型RAW降噪、多维画质评价、参数鲁棒性和CUDA分块部署。所有模块支持独立旁路、中间结果、参数记录和专项回归测试；未取得真实标定数据的LSC/CCM/LDC及跨相机结果会明确标注边界。

## 13. 最终完成判定

项目在以下条件全部满足后进入最终release：

1. Phase 1和Phase 2必补模块完成并通过模块级测试；
2. 所有新增模块bypass时，当前正式U-Net结果在容差内不变；
3. Phase 5生成统一传统/学习pipeline对比报告；
4. Phase 7能生成标准RGB和YCbCr/原始视频格式输出；
5. SID release smoke仍为0失败，显存不超过RTX 3060 Ti容量；
6. README可以从环境、数据、测试一路复现到单图/批量推理；
7. 文档明确区分已验证结果、合成验证和待真实标定项目。
